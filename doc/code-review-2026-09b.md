# kynovo full engineering review (2026-09b)

**Scope**: `code/` (12 files / 19,268 lines), `tests/` (15 files / 19,402 lines), `build.sh`, `tools/`,
`doc/`, `.github/workflows/`, `ops/`, workspace hygiene.
**Method**: a green top-tier gate as the baseline, six independent read-only module audits, then
**every finding below re-opened and verified by me** at the cited line (findings I could not verify are
listed separately in §3 and are not counted as facts).
**Baseline achieved in this session**: `./build.sh regress full` → `REGRESS|full|pass=13 fail=0
duration=307s`, i.e. build (0 error / 0 warning) + 4 unit suites + selftest + cleanliness + CLI smoke +
20,000-iteration fuzz + 2,000-cluster fuzz + 10-cluster linearizability + 24-round release soak, all green
on the reviewed HEAD (`1b6ecc9`).

**Judgement in one paragraph.** The engineering is strong where it is hardest to get right: the Raft
core's commit rule is *stricter* than the paper (current-term-only advance plus `leadership_confirmed`,
§5.4.2/§6.4), the application never reads raft internals for decisions, the snapshot is written and
verified without any temp-file rename, and the panic paths print reasons. What this review found is a
different class: **the project's own verification apparatus has holes that let regressions through
silently**, and the places where "the rule is only in prose" have quietly accumulated. The single most
valuable finding (A1) is a gate rule that has been advertising a budget of 7 while enforcing 162 — it
made the ratchet I myself reported as "at its floor" effectively empty. Second is a real use-after-free
write in the server's connection-teardown path (D1), which is the exact shape of a rule the project
already wrote down once.

## 2. What is done well (verified, with evidence)

- **Raft's commit rule is stricter than the paper**: current-term-only advance (`raft.h:2000`) plus a
  leadership-confirmation requirement, and the follower's commit cap follows Figure 2
  (`raft.h:3671-3681`). Pre-vote, deferred vote/append responses gated on `persist_gen`, and durable
  match indices are all present (`raft.h:137-56, 3183-3272, 3708`).
- **The mechanism/policy split holds**: the application reads raft facts from the ready bundle only
  (`kserver.h:4705`), and the `raft->config_*` ratchet is at **0** (`check-principles.py:157`).
- **Snapshot discipline**: capture/finish on the owner thread (`kserver.h:4668, 4270-4272`), no temp-file
  rename, trailer + read-back + end probe before the snapshot is trusted or old files are unlinked
  (`kserver.h:4178-4193, 4276-4281`).
- **Gate self-consistency where it counts**: `reg_gate` takes the exit code directly (never through a
  pipe) and requires a verdict line (`build.sh:320-332`), the build layer counts only real compiler
  diagnostics and requires the binary to exist (`:339, 353`), and the linearizability layer demands a
  non-zero decided-history count (`:389`) — the one layer that cannot be fooled by an empty run.
- **The oracle protects itself**: `lincheck.h` carries a case that must fail, a memo-key regression and a
  2,000-history cross-check against a naive oracle (`lincheck.h:185-276`), and it self-tests before use.
- **Instrumentation hygiene is real**: no leftover tags anywhere (`check-principles.py:137` matches only
  its own rule text), and the three fuzzers are deterministic (self-written PRNG, explicit `elapsed_ms`,
  no `srand`/`rand`, seed printed).
- **Zero-warning contract** is enforced on the pinned toolchain and honestly downgraded on foreign ones
  (`build.sh:341-355`).

## 4. Retractions (errors made while producing this review or earlier in the session)

1. **My claim that the C99 rule-9 ratchet had reached its floor of 7** and was self-certified by
   injection: **wrong in effect** — the threshold is 162 (A1). The injection I remembered did turn the
   gate red *at the time*, because then the site count sat at the slice boundary; as files were converted
   the slice was never moved, so the ratchet silently opened. Corrected in the ledger (§K).
2. **My probe claiming `mem://` + thread runtime fails every write (10/10):** **wrong — my instrument**.
   The comparison was `[ "$out" = "ok" ]` against a line that ends `ok\r\r\n`, so `tail -1` yielded `ok\r`
   and every success was scored as a failure. The combination works (STATS showed a healthy leader);
   the mem-backend race stays structural (C3).
3. **The doc audit's claim that CI's LF step makes CI permanently red: refuted** by the CI job log — the
   step passes *vacuously* (no `git` on PATH, 0 files checked). The real defect there is a green line that
   means "checked nothing" (F1).
4. **The test audit's claim that a do-nothing fuzz can wear the same green line: partially refuted** — true
   for the two raft layers, false for the gate, which goes red on the linearizability layer (A3).
